# Phase 02 — Cross-Generator Generalization and Robustness

[← Project overview](../README.md) · [Notebook](02_cross_generator_robustness.ipynb)

## Objective

Evaluate whether a **real-versus-fake** detector trained on a single GAN family (ProGAN) remains accurate when tested on images generated by other methods and when images undergo common transformations.

This is a **separate binary-classification experiment**. It is not a direct continuation of the three-class Phase 01 checkpoint.

## Training setup

**Data source:** [AIGIBench](https://huggingface.co/datasets/HorizonTEL/AIGIBench), Setting-I (ProGAN), categories **car**, **cat**, **chair**, and **horse**.

| Train / validation | 115,218 / 28,806 |
| Image size | 224 × 224 |

| Model parameters | 1,635,970 |

| Scheduler | OneCycleLR |
| Regularization | Label smoothing 0.1, feature-space mixup α=0.2, gradient clipping to 1.0 |

**Important dataset distinction:** The author-supplied Phase 01 dataset reference is GenImage, whereas this notebook's actual downloads are from AIGIBench. AIGIBench's Setting-I ProGAN training set originates from ForenSynths, according to the benchmark documentation; it is not the same as training directly on a GenImage subset.

The model uses the same **15-channel PiD + signal feature extraction** and custom CNN backbone described in [the project overview](../README.md), with a two-output classifier head.

## Robustness protocol

Each of the **eight selected AIGIBench test subsets** includes 500 real and 500 fake images. Four variants are evaluated:

1. **Original:** input without additional degradation.
2. **JPEG:** JPEG re-encoding at quality 50.
3. **Noise:** Gaussian noise with standard deviation 4/255 on normalized pixel values.
4. **UpDown:** nearest-neighbor downsampling by a factor of two followed by upsampling.

The subsets used were ProGAN, WFIR, R3GAN, GLIDE, DALLE-3, BlendFace, FaceSwap, and BLIP. This selection includes the in-domain training generator (ProGAN); **it is not an eight-subset unseen-generator-only score**, and it is not the full 25-subset benchmark.

## Results

**Best in-domain ProGAN validation accuracy:** **99.93%** (best recorded value 0.9993, epoch 26). This value should not be confused with the cross-generator test results below.

### Accuracy by test subset (%)

| Test subset | Original | JPEG | Gaussian noise | UpDown |
| --- | ---: | ---: | ---: | ---: |
| ProGAN | 99.6 | 50.0 | 49.9 | 82.1 |
| WFIR | 62.7 | 50.0 | 50.4 | 65.8 |
| R3GAN | 72.4 | 50.0 | 50.9 | 74.5 |
| GLIDE | 67.1 | 50.0 | 40.7 | 55.2 |
| DALLE-3 | 55.5 | 50.0 | 55.7 | 60.8 |
| BlendFace | 17.5 | 50.0 | 29.8 | 30.3 |
| FaceSwap | 25.0 | 50.0 | 24.1 | 38.8 |
| BLIP | 82.6 | 50.0 | 56.0 | 71.2 |
| **Mean (8 subsets)** | **60.3** | **50.0** | **44.7** | **59.8** |

The **unweighted average of the four mean accuracies is 53.7%**.

Results and logs: [CSV table](../results/phase-02/subset_accuracy.csv) · [Full experiment log](../results/phase-02/training_log.txt).

### Interpretation

- In-domain ProGAN classification was strong, but performance differed greatly across generators.
- The two evaluated face-manipulation subsets were difficult: **17.5%** on BlendFace and **25.0%** on FaceSwap with original inputs.
- Under JPEG compression, every evaluated subset reported **50.0% accuracy** and **0.0% fake-class accuracy**, indicating collapse to a single predicted class (real).
- Adding noise also reduced the overall mean relative to original images.

These results illustrate a key research challenge: **strong validation performance on the training generator does not imply reliable detection of other generated or manipulated images**.

## Running the notebook

1. Use a Kaggle environment with a compatible PyTorch CUDA setup and sufficient temporary storage. Exact environment versions were not recorded.
2. Install any missing dependencies from the root [`requirements.txt`](../requirements.txt).
3. Review `TMP_DIR`, `WORK_DIR`, and the available storage. The notebook downloads dataset ZIP files from Hugging Face.
4. Open [the Phase 02 notebook](02_cross_generator_robustness.ipynb), configure the notebook's paths and run the cells sequentially.
5. The organized copy scopes cleanup to a project-specific optional cache; unlike the original uploaded notebook, it does **not** delete files across the shared `/tmp` or `/var/tmp` directories.
6. Results will be written under the configured working directory, including `task2_results.json`.

**Compute requirement:** The full experiment uses more than 144,000 training/validation images plus repeated downloads and evaluation of the eight test subsets. It should not be treated as a quick CPU-only example.
